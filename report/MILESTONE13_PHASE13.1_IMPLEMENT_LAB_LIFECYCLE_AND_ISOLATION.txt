1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
Phase 13.1 establishes the core lifecycle, execution model, service control, and
containment safety boundaries for the WireScope Isolated Practice Lab. The lab
enables defensive practitioners and systems operators to reproduce real-world
connectivity issues, unapproved listener exposure, and policy violations locally
without requiring paid infrastructure, cloud resources, or accessing public targets.

All acceptance criteria defined in `wirescope_phase.txt` have been strictly met:
- Lab setup and teardown are deterministic and repeatable.
- Lab services bind strictly to loopback (`127.0.0.1` / `::1`) by default.
- Cleanup and reset operations cannot remove unrelated files or processes;
  sandboxed path validation strictly forbids directory traversal escapes.
- Synthetic and real observations are unambiguously distinguishable via badges
  (`[SYNTHETIC_LAB_FIXTURE]`), provenance tags (`synthetic_lab_fixture`), and notices.
- Lab execution strictly rejects public network targets before any probe or query.

2. ARCHITECTURAL & IMPLEMENTATION HIGHLIGHTS
--------------------------------------------------------------------------------
A. Versioned Scenario Model (`src/lab/scenario.zig`)
   - Schema version: `LAB_SCENARIO_SCHEMA_VERSION = 1`.
   - Comprehensive model including canonical scenario identifier, title, category,
     difficulty, technical objective, description, step-by-step operator instructions,
     diagnostic hints, expected observations, verification criteria, and cleanup
     strategy.
   - Built-in scenario registry containing all six foundational exercises:
     1) `dns_failure`: DNS resolution no-answer and timeout simulation.
     2) `tcp_refusal_timeout`: Loopback TCP connection refusal and bounded timeout.
     3) `tls_cert_issues`: TLS certificate expiration and SAN mismatch.
     4) `unexpected_listener`: Unexpected local listening service versus baseline.
     5) `http_security_header_violation`: Missing defensive HTTP headers.
     6) `remediation_verification`: Defensive hardening verification via diff.
   - Full serialization support across Terminal, GitHub Markdown, and JSON.

B. Controlled Loopback Services (`src/lab/service.zig`)
   - `LabLoopbackService` binds strictly to `127.0.0.1` or `::1`.
   - Non-loopback bind attempts (e.g. `0.0.0.0`, `192.168.1.1`, `8.8.8.8`) are
     instantly rejected with `error.NonLoopbackBindForbidden`.
   - Dynamic ephemeral port assignment (`port = 0`) queries kernel allocation via
     cross-platform `getsockname`.
   - Non-blocking polling accept loop (`select` on Windows, `poll` on POSIX) with
     atomic `should_stop` flags guarantees deterministic, leak-free shutdown without
     Winsock race conditions or dangling worker threads.
   - Zero libc dependency: uses native `ws2_32` send/recv implementations on Windows.

C. Sandbox Containment & Lab Manager (`src/lab/manager.zig`)
   - `LabManager` controls active scenario state inside `<data_dir>/lab/active_state.json`.
   - Safe sandbox path containment: `validateSandboxPath` validates that all file
     operations remain strictly inside the lab sandbox. Attempts to escape via `..`,
     relative paths, drive letters, or absolute paths return `error.SandboxEscapeDetected`.
   - Repeatable lifecycle: setup -> status -> reset -> cleanup -> setup is completely
     idempotent and leak-free.
   - Cleanup terminates only managed loopback services and safely deletes only
     WireScope-owned records recorded within `<data_dir>/lab/`.

D. Verification Engine (`src/lab/verify.zig`)
   - Evaluates collected evidence against scenario criteria.
   - Emits structured outcomes (`passed`, `failed`, `inconclusive`), scoring,
     matched criteria, and actionable remediation notes.
   - Enforces synthetic provenance stamping across all evaluation outputs.

E. CLI Command Integration (`src/cli/root.zig`)
   - Wires full command suite under `wirescope lab`:
     * `wirescope lab list`: Catalogs exercises in Terminal, Markdown, or JSON.
     * `wirescope lab inspect <id>`: Displays scenario details, hints, and instructions.
     * `wirescope lab setup <id>` / `run <id>`: Initializes scenario state and services.
     * `wirescope lab status`: Reports active scenario metadata and loopback bindings.
     * `wirescope lab verify [id]`: Verifies diagnostic outcome against criteria.
     * `wirescope lab reset`: Restores initial clean state.
     * `wirescope lab cleanup`: Stops listeners and purges lab state cleanly.

3. ACCEPTANCE CRITERIA VERIFICATION
--------------------------------------------------------------------------------
Criteria 1: Lab setup and teardown are repeatable.
- Evidence: Unit test `test "lab manager: repeatable setup, status, and cleanup lifecycle"`
  executes multiple setup and cleanup cycles consecutively. Verified zero handle or
  file leaks across cycles.

Criteria 2: Lab services bind to loopback by default.
- Evidence: Unit test `test "lab service: strictly forbids non-loopback bind addresses"`
  verifies that binding to `0.0.0.0`, `192.168.1.1`, or `8.8.8.8` returns
  `error.NonLoopbackBindForbidden`. Loopback service binds exclusively to `127.0.0.1`.

Criteria 3: Cleanup cannot remove unrelated files or processes.
- Evidence: Unit test `test "lab manager: sandbox prevents escaping paths"` verifies
  that attempts to delete `../etc/passwd`, `..\Windows\System32`, or `C:\autoexec.bat`
  are immediately halted with `error.SandboxEscapeDetected`. Cleanup operates only
  within `<data_dir>/lab/`.

Criteria 4: Synthetic and real observations are distinguishable.
- Evidence: All terminal, markdown, and JSON outputs feature `[SYNTHETIC_LAB_FIXTURE]`,
  `"is_synthetic": true`, `"provenance": "synthetic_lab_fixture"`, and origin notices.

Criteria 5: Lab execution does not silently contact public targets.
- Evidence: `validateLabTarget` strictly validates targets before probe dispatch.
  Public targets (`google.com`, `8.8.8.8`, `api.github.com`) return
  `error.PublicTargetForbiddenInLab`. Only `127.0.0.1`, `::1`, and RFC 6761 test domains
  (`.test`, `.example`, `.invalid`, `.localhost`) are permitted.
