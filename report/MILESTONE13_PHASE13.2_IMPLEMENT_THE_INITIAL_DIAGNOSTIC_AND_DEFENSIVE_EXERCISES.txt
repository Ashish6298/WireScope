1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
Phase 13.2 delivers the complete implementation of the six foundational practice lab
exercises defined in `wirescope_project.txt`. These exercises provide hands-on,
evidence-driven diagnostic simulations and defensive security audits operating 100%
locally on loopback without requiring paid services, cloud subscriptions, or contacting
public targets.

Every exercise adheres strictly to defensive training standards:
- Clear, unambiguous articulation of Objective, Expected Evidence, Observed Evidence,
  Technical Interpretation, Operational Limitations, and Defensive Resolution.
- Strict isolation of test-only certificates and fixtures under `<data_dir>/lab/fixtures/`.
- Concrete demonstration of defensive remediation verification: configuration fixes
  applied between consecutive assessments are verified via baseline diffing and policy
  evaluation, proving that previously flagged findings are marked RESOLVED.
- Absolute prohibition of exploit delivery, brute-forcing, stealth, evasion, or
  destructive capabilities.

2. DETAILED EXERCISE BREAKDOWN
--------------------------------------------------------------------------------
Exercise 1: DNS Resolution No-Answer and Timeout Simulation (`dns_failure`)
- Target: `unresolvable-lab.test` (RFC 6761 reserved testing domain)
- Objective: Practice identifying NXDOMAIN errors versus resolver timeouts and
  verifying deterministic query outcome classifications.
- Expected Evidence: Zero IP address answers returned; resolution status 'failed'
  with failure category NXDOMAIN or Timeout.
- Observed Evidence: Simulated DNS resolution query completed with 0 answers; status
  flagged as failed; failure classified as NXDOMAIN_OR_TIMEOUT. Zero public root
  servers contacted.
- Technical Interpretation: The requested domain name does not exist on authoritative
  servers or the resolver failed to reach authoritative root servers.
- Operational Limitations: Local DNS diagnostics cannot determine whether an
  upstream network device is deliberately filtering traffic versus true zone non-existence.
- Defensive Resolution: Verify hostname spelling, inspect authoritative zone records,
  or verify local DNS resolver configuration.
- Generated Security Finding: `WS-FINDING-DNS-FAILURE` (Severity: Low).

Exercise 2: TCP Connection Refusal and Bounded Timeout (`tcp_refusal_timeout`)
- Target: `127.0.0.1:<ephemeral_closed_port>`
- Objective: Learn to reliably differentiate between 'Connection Refused' (service
  down/closed port) and 'Connection Timeout' (silent drop/unreachable).
- Expected Evidence: Immediate TCP connection error classified as 'refusal' with
  OS error WSAECONNREFUSED / ECONNREFUSED in <5ms.
- Observed Evidence: TCP connection attempt to closed loopback port returned immediate
  RST refusal (<5ms) with socket error WSAECONNREFUSED / ECONNREFUSED.
- Technical Interpretation: The host network stack is active and responsive, but no
  application daemon is bound to and listening on the designated port.
- Operational Limitations: Some stateful firewalls are configured to inject TCP RST
  packets to disguise packet rejection as a closed port.
- Defensive Resolution: Verify that the target service daemon is started and actively
  bound to the expected interface and port.
- Generated Security Finding: `WS-FINDING-TCP-REFUSAL` (Severity: Medium).

Exercise 3: TLS Certificate Expiry and Hostname Mismatch (`tls_cert_issues`)
- Target: `https://127.0.0.1:8443/`
- Fixture Isolation: `<data_dir>/lab/fixtures/test_cert_mismatch.pem` (isolated self-signed X.509)
- Objective: Detect expired certificates and SAN (Subject Alternative Name) hostname
  mismatches and generate structured findings without polluting the OS trust store.
- Expected Evidence: TLS handshake inspection identifies SAN mismatch (requested host
  not in SAN list ['mismatch.lab.test']) or notAfter date prior to current time.
- Observed Evidence: TLS inspection of isolated fixture identified SAN mismatch (CN='mismatch'
  != requested '127.0.0.1') and expired certificate validity (notAfter=2020-01-02). Host
  trust store untouched.
- Technical Interpretation: Browsers and API clients will abort TLS handshakes to this
  endpoint due to trust or identity mismatch.
- Operational Limitations: Test-only self-signed certificates lack a trusted CA chain
  and are intended solely for local validation exercises.
- Defensive Resolution: Generate or issue a new X.509 certificate that includes the
  canonical hostname in 'subjectAltName' and has a valid date range.
- Generated Security Finding: `WS-FINDING-TLS-SAN-MISMATCH` (Severity: High).

Exercise 4: Unexpected Local Listener Exposure versus Baseline (`unexpected_listener`)
- Target: `127.0.0.1:<ephemeral_listener_port>`
- Objective: Detect unexpected open ports and newly introduced listening daemons using
  deterministic baseline diffing.
- Expected Evidence: Baseline diff marks new listener as 'added'; exposure policy
  generates unapproved listener finding.
- Observed Evidence: Listener inventory detected active socket on ephemeral port.
  Baseline diff against approved baseline flagged socket as ADDED (unapproved listener).
- Technical Interpretation: An unapproved service has opened a listening socket on
  the host, increasing the attack surface.
- Operational Limitations: Process attribution requires administrative privileges on
  some operating systems; unprivileged execution identifies port and IP but may not
  identify binary path.
- Defensive Resolution: Terminate unauthorized process or, if legitimate, approve
  the service into the baseline profile.
- Generated Security Finding: `WS-FINDING-LISTENER-UNAPPROVED` (Severity: Medium).

Exercise 5: HTTP Security Header Policy Violation (`http_security_header_violation`)
- Target: `http://127.0.0.1:<ephemeral_http_port>/`
- Objective: Identify missing HTTP defensive security headers and generate policy
  failure reports without accessing external servers.
- Expected Evidence: HTTP observation captures 200 OK with missing HSTS, CSP, and
  X-Frame-Options; policy check flags failures.
- Observed Evidence: HTTP audit received status 200 OK without HSTS, CSP, and
  X-Frame-Options. Policy evaluation flagged 3 check failures.
- Technical Interpretation: Absence of these headers leaves web clients vulnerable
  to MIME sniffing, iframe embedding (clickjacking), and protocol downgrade attacks.
- Operational Limitations: Header inspection only audits outer HTTP transport metadata,
  not the security of underlying application code or authorization logic.
- Defensive Resolution: Configure web server or reverse proxy to return required
  defensive HTTP security headers (HSTS, CSP, X-Frame-Options, X-Content-Type-Options).
- Generated Security Finding: `WS-FINDING-HTTP-MISSING-SECURITY-HEADERS` (Severity: Medium).

Exercise 6: Defensive Remediation and Diff Verification (`remediation_verification`)
- Target: `http://127.0.0.1:<ephemeral_http_port>/`
- Objective: Demonstrate closed-loop security posture improvement by capturing
  before-and-after assessments and validating remediation resolution.
- Expected Evidence: Assessment 1 shows policy violations; Assessment 2 shows 100%
  policy pass; baseline comparison confirms prior findings are resolved.
- Observed Evidence: Assessment 1 flagged missing headers finding. Remediation was
  applied by hardening mock service headers. Assessment 2 confirmed 100% policy PASS.
  Deterministic baseline diff confirmed prior finding WS-FINDING-HTTP-MISSING-SECURITY-HEADERS
  is marked RESOLVED. Zero regressions and 0 new findings detected.
- Technical Interpretation: Remediation changes are verifiable and measurable: the diff
  proves the configuration fix took effect.
- Operational Limitations: Remediation verification proves current compliance; automated
  regression testing is required to prevent configuration drift over time.
- Defensive Resolution: Integrate baseline checks into CI/CD deployment pipelines.
- Remediation Verification Outcome: PASSED (Policy 100% PASS, Finding Resolved).
